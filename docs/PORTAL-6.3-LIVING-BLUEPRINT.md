# Portal 6.3 — Living Intelligence Blueprint

Status: sandbox-first, branch-isolated architecture contract.

## Mission
Portal 6.3 evolves The Portal from an archive of imagined futures into a persistent possibility engine that can originate, test, revise, supersede and kill hypotheses while preserving a complete epistemic ancestry.

The system optimizes for progressively better models, not for always producing an answer.

## Core loop
PERCEIVE → REMEMBER → CONNECT → QUESTION → REASON → PLAN → TOOL → ACT → OBSERVE → VERIFY → LEARN → COMMUNICATE → ANTICIPATE → EVOLVE.

## Faculties
1. Cortex — decomposition, causal/counterfactual reasoning, uncertainty, competing hypotheses.
2. Hands — explicit tool capability map, selection, execution and verification.
3. Executive — goal/constraint/subproblem/strategy/action/replan graph.
4. Memory — working, episodic, semantic, procedural, relational, prospective and epistemic memory.
5. Voice — audience-aware communication with calibrated uncertainty and ancestry explanations.
6. Mycelium — strengthening, weakening, merging, splitting, dormancy, rebirth and death of connections.
7. Metacognition — continuously challenges assumptions, tool choice, memory reliability, anchoring and problem framing.

## Evolutionary Cognition Engine (ECE)
ECE maintains diverse populations of hypotheses, plans, tool strategies, representations and predictions. Variation includes mutation, recombination, causal inversion, counterfactual mutation, analogy and adversarial mutation. Selection is multi-objective and diversity-preserving; no single scalar reward may silently dominate truth, safety or calibration.

Suggested fitness dimensions: predictive accuracy, evidential support, novelty, usefulness, robustness, cost efficiency, calibration and constraint compliance.

Cognitive niches may include explorers, scientists, engineers, skeptics, strategists, toolsmiths, archivists and contrarians. Hypothesis populations co-evolve with critic populations whose job is to falsify them.

## Open-ended possibility space
Imagination is not constrained to established physics. Candidates may explore extrapolated physics, counterfactual worlds, altered laws, unknown-law models, mathematical universes and synthetic ontologies. This is an exploration permission, never an evidence shortcut.

Every claim carries an epistemic class: OBSERVED, SOURCE_SUPPORTED, INFERRED, EXTRAPOLATED, SPECULATIVE, COUNTERFACTUAL, UNKNOWN_LAW or CONSTRUCTED.

Constraints enter when a candidate claims correspondence with reality or attempts real-world action.

## Hypothesis genome
Every hypothesis must preserve:
- stable ID and generation;
- parents/ancestors and mutation operators;
- supporting and contradicting evidence;
- assumptions and epistemic class;
- predictions;
- falsifiers and hard-kill conditions declared before outcomes when possible;
- confidence/calibration history;
- tool calls and observations;
- lifecycle state and superseding descendants.

Lifecycle: EMERGING → LIVING → CONTESTED → DORMANT → DEAD, with explicit REBORN transitions when new evidence warrants reconsideration.

Dead hypotheses remain in the fossil record and may contribute reusable fragments without silently becoming true again.

## Containment
GREEN: hypotheses, plans, retrieval/tool strategies and sandbox simulations may evolve autonomously.

AMBER: prompts, workflows, memory policies, tool-selection policies and evolutionary parameters require evaluation gates before promotion.

RED: production source code, permissions, credentials, safety boundaries, deployment configuration, production data and main may not self-modify.

Evolution proposes changes; it never silently deploys them.

## Sandbox acceptance protocol
Seed a deliberately incomplete world with heterogeneous observations, noise, coincidences, hidden relationships, delayed evidence and contradictions. Do not provide a target hypothesis.

Portal 6.3 passes the decisive experiment only if an unattended run can:
1. originate at least one non-obvious candidate absent from prompts/seed statements;
2. produce a machine-auditable ancestry from evidence to inference;
3. declare falsification conditions;
4. make a prospective prediction or request a discriminating observation/tool experiment;
5. select and verify useful tools without a prescribed sequence;
6. recall relevant prior experience;
7. adapt its plan after failure;
8. communicate the candidate, uncertainty and ancestry clearly;
9. reduce confidence when contradictory evidence arrives;
10. autonomously weaken, supersede or kill the hypothesis when warranted.

Evaluators should not know a single required discovery in advance. Score novelty, derivability, falsifiability, calibration, self-correction, utility, tool competence, memory relevance, problem-solving quality and communication.

## First implementation boundary
The first implementation establishes contracts and a deterministic sandbox substrate only: no autonomous production mutation, no production database migration, no merge to main. Runtime evolution is introduced behind explicit feature flags after contracts and tests are reviewable.
